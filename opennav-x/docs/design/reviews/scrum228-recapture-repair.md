# SCRUM-228 — preserve owned chart controls during GTK recapture

The frozen `1356fd1603aacbea04d7081d16331e9a181180bb` application can briefly raise its main window above all four mapped chart-control windows when a stale alert changes layout. The earlier [read-only investigation](scrum228-gl-stale-overlay.md) recorded that inversion and recovery; logical `visible=true` alone could not detect the occlusion.

A diagnostic interposer left the frozen executable and X11 arguments unchanged, recording window raises plus the wx event-handler method active at each call. It identified `MyFrame::OnRecaptureTimer(wxTimerEvent&)`, ELF offset `0xaaeb30`, raising owner window 2097401 at monotonic 41263.817676 and 41263.819079 during the stale transition. The source schedules this recapture one second after `ProcessCanvasResize`. Ordinary backtraces omitted this function because the optimized ELF tail-jumps to the virtual Raise method; recording the event functor disambiguated the caller. The attributed baseline still passed all 26 route checks. The trace does not instrument marine data or change frame ordering.

The xnav patch now calls `opennav::AfterFrameRecapture()` immediately after that existing Raise, only for GTK builds with OPENNAV_X. The integration checks the active SKAGER shell and asks it to restack its already visible chart controls. `XNavFloatingSurface::RestackAboveOwner()` rejects hidden or unmapped native surfaces and uses the same `gdk_window_restack(surface, owner, true)` primitive already used by Present. The ordinary Present path retains its existing deferred-show, movement, shape and restack behavior. No generic event filter, new timer, focus call, global topmost state or navigation change was introduced. The existing sheet/card guard still returns before Raise. Legacy and Safe retain their original behavior; Standard chart style inside the SKAGER shell receives the same overlay repair. The new hook is absent on Windows.

Focused verification:

- **34 native GTK checks pass.** The fixture extracts the actual patched recapture callback, integration gate and Shell restack loop verbatim and executes them with real wx/GTK owned windows. An actual owner Raise first inverts their native X order; after a native paint opportunity the control is visibly covered. The callback restores order before returning and through the next event cycle. The resulting control receives a real pointer activation, not a canvas click. Hidden state, geometry, focus, the transient guard, Legacy behavior and an unrelated higher window are checked.
- **Negative control fails at the repair assertion.** Removing only the new callback hook leaves the real owner above its mapped control. No timing assertion or pixel tolerance is relaxed.
- **All 17 existing Linux floating-surface lifecycle checks pass** in both positive and negative runs; the existing test source is unchanged, including its 12 platform-independent/Windows checks.
- The xnav patch's complete frame section applies cleanly to the pinned original. **Four actual production objects compile:** `FloatingSurface.cpp`, `Shell.cpp`, `OpenCPNIntegration.cpp`, and the patched `ocpn_frame.cpp`, using the integrated production flags and private outputs.
