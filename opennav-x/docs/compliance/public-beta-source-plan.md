# Public beta source and license delivery plan

This is a bounded implementation audit for SCRUM-57. It records the current
file boundaries and the release mechanism that still needs to be made explicit;
it is not legal advice or a license determination.

## Audited boundaries

| Component | Current boundary and evidence | Delivery implication |
| --- | --- | --- |
| OpenNav X product and integration patches | Root `LICENSE` is GNU GPL v2. The source archive recipe in `tools/source_package.py` includes the exact product checkout, root CI recipes, and the four committed OpenCPN integration patches under `patches/`. | A paid access offer must not make the GPL source conditional. The binary, applicable notices, and corresponding source need an independent public path. |
| OpenCPN | `upstream.lock.json` pins tag `Release_5.12.4` at `37fd0cddb7334fe489e9f18aa163977a9c5c84f7`; the native workflows fetch that tag, and `tools/source_package.py` requires that exact integrated baseline. | Keep the OpenCPN prerequisite and its source/license records separate from the commercial account and download service. |
| wxWidgets | `docs/third-party/wxWidgets-3.2.8/{licence.txt,lgpl.txt,gpl.txt,provenance.json}` are copied by `tools/package-preview.py`. | Retain those notices in every shipped package that contains the corresponding runtime/application files. |
| OpenSSL | `docs/third-party/OpenSSL-3.5.9/{LICENSE.txt,provenance.json}` now replace the prior 3.0.5 notice input in `tools/package-preview.py`; the 3.0.5 record remains for historical evidence. | Retain the license and provenance with the package and source record. |
| MSVC runtime | `tools/package-preview-windows.ps1` selects the installed x86 MSVC redistributable directory and `tools/package-preview.py` copies its DLLs app-locally. | Record the exact selected runtime files and applicable Microsoft redistribution terms in the release evidence. |

The package script also copies the root `LICENSE`, OpenCPN license files found in
the build's `upstream/OpenCPN` tree, creates `docs/SOURCE_AND_LICENSES.md`,
`FILE_SHA256.json`, `OpenNavX-Beta2-source.zip`, and a ZIP checksum. It does not
turn the generated notice page into a complete dependency inventory by itself.

## Exact release mapping and intended delivery

For a release candidate, bind all outputs to one exact product commit (the
current audit checkout is `334eddc`) and the pinned OpenCPN commit above. The
native build must be produced by the existing baseline/prototype workflows, then
`tools/package-preview-windows.ps1` must invoke `tools/package-preview.py` from
that same checkout. The source archive must be generated by
`source_package.create_source_archive`, which refuses a mismatched product
commit, dirty product checkout, dirty staged checkout, or wrong OpenCPN
baseline, and records per-file SHA-256 values in `SOURCE_REFERENCE.json`.

The release set described by `docs/public-beta-contract.md` is:
`Setup.exe`, `Portable-Recovery.zip`, `corresponding-source.zip`,
`SHA256SUMS.txt`, signed update metadata, release notes, and a license/notice
package. The current candidate workflow uploads the source ZIP and package
artifacts only after its qualification condition succeeds. The public delivery
path should be a version-specific release page or legal footer link that points
to the exact source archive and notice package, independently of paid account
entitlement. Paid services may protect downloads of the product and support;
they must not restrict the source rights or source availability granted by the
applicable licenses.

## Current enforcement and missing release gate

Already enforced by repository code or CI:

- `tools/source_package.py` checks the exact product revision, clean checkout,
pinned OpenCPN baseline, committed workflow bytes, integration patch hashes,
symlink modes, and per-file source hashes.
- `tools/test-source-package.py` exercises mismatched commits, dirty/staged
source, wrong upstream, missing/changed workflows, and archive integrity.
- `tools/package-preview.py` refuses missing product executables/runtime DLLs,
fixture/demo content, commit identity mismatches, and non-Beta-2 version data;
it copies the root, OpenCPN, wxWidgets, and OpenSSL notices.
- `.github/workflows/opennav-baseline.yml` runs source-package tests and carries
the corresponding source ZIP in the qualified artifact set.

Still missing before public release:

1. A release gate must inspect the assembled release directory and fail unless
`Setup.exe`, portable ZIP, source ZIP, checksums, update metadata/signature,
release notes, and license/notice package are all present and tied to one
commit.
2. That gate must verify the notice package's required files and its
version-specific source URL, rather than relying only on the packager's
copying code.
3. The public release/legal page must publish the exact source and notice links;
there is no repository-enforced public URL or release-page check in this audit.

The next implementation should add that narrow assembly/public-link check after
its Jira representation. It should not broaden into an unbounded dependency
inventory or change payment, download authorization, or OpenCPN installation
behavior.

## License review boundary

The pinned OpenCPN `CMakeLists.txt` header grants GPL version 2 or any later
version (`upstream/OpenCPN/CMakeLists.txt:9-13`). That is evidence for the
OpenCPN project header, not a conclusion for every integrated component. The
source tree carries separate GPL, LGPL, and component-specific notices, and
OpenSSL 3.5.9 carries its Apache-2.0 license. Component compatibility and
required attribution/notice delivery remain open review items.
