# SCRUM-217: native tool-fact contract probe

This is a short Windows build-tool check, not application or release
qualification. The product candidate remains
`f1e2cde8fcbf92826d648007b267cc0f5320aa55`; no candidate branch was moved.

The probe uses a disposable C project generated by actual Visual Studio 2022
and CMake under `vcvarsall x86`. It reads the generated Win32 project, compiler
metadata and cache rather than supplying fabricated compiler/toolset fields.
It exercises capture, unchanged verification, changed environment rejection,
changed generated toolset rejection, and verification after restoration.
The parent entrypoint runs in Windows PowerShell 5.1.

## First observed failure

The native job completed with a test-harness failure after real zlib-child
capture, unchanged verification and changed-INCLUDE rejection passed.
The generated file contains the exact `CMAKE_VS_PLATFORM_TOOLSET=v143` value,
but has Windows CRLF line endings. The test's multiline regex ended with `$`
without accounting for the carriage return, so its prerequisite assertion
reported `Observed v143 toolset fact missing` before the toolset-tamper case.
The production helper reads individual lines and had accepted the same file.
The remaining cases, including the parent environment, did not run.

Retained artifact `11169743846` has 58,462 bytes and SHA-256
`60561db37d756dcb30107be707af36902dfe6fbed6db6fc04b95462cc07d3137`.
The archive digest, size, safe paths and bounded extraction were verified;
actual summary, stages and generated file bytes were inspected under
`evidence/local/native-tool-facts-36878016002/`.
Correct the test's line-ending handling without relaxing the exact toolset
requirement, then execute a new native run. This failure does not affect the
separate frozen product candidate, which does not contain these reuse hooks.
