# Installed terminal cleanup ownership

SCRUM-27. This source contract extends the explicit protected retirement path;
it is not acceptance of full installed uninstall, maintenance UI, repair,
package delivery or boat operation. Native and installed gates remain separate.

`--maintenance=uninstall-installed` requires the independently approved original
client request, original startup publication and original baseline artifact.
The same `MaintenanceOwner` prepares startup and installed custody before asking
its one live broker to fence, restore/drain startup descendants, and retire the
closed completed generation lineage. An updated or rolled-back selected head
must remain in that lineage; pending or ambiguous history refuses. The original
startup anchor always belongs to the original approved baseline.

The installed owner resolves the approved user's actual LocalAppData, fixed
`OpenNavXAlpha1` integration root, exclusive existing transaction lock and fixed
Programs/SKAGER menu. Mutable state may locate only a bounded generation below
that root. It cannot authorize cleanup paths or hashes. The retained original
approved ZIP independently supplies exact installed member sizes/hashes and a
closed installer-helper copy mapping. Original matching members receive native
read/DELETE custody before any terminal broker effects. Missing members are
already absent; changed, unknown or unapproved members remain. Recovery and
stock OpenCPN remain retained and are never recursively removed. No profile,
chart, route, plugin, connection or other navigation data is a cleanup target.

During startup restoration, a stock or unknown original normal shortcut remains.
An original link pointing exactly to the verified integration may instead be
retired, using its original handle, into the fixed original startup recovery
folder. Fixed Legacy and maintenance menu links require exact target, arguments
and working-directory matches. The maintenance link's target is a narrowly
recognized current-generation `Maintain.exe`; retiring that link does not grant
permission to remove that executable or its payload. Arbitrary link targets are
never launched or followed.

Only a matching final native broker witness permits integration-link retirement,
service disable and STOP. After the original broker process exits successfully,
cleanup rechecks the same retained file, startup, stock and service owners. It
must not reuse the now-expired live process witness as a post-exit check. Verified
members are marked for deletion through their original handles. Original
`state.json` moves without replacement to `retired-state.json`; a replacement
active state or colliding retired name refuses. Recovery bytes remain.

The fixed approved-SID Windows uninstall registration uses an original retained
HKEY plus an explicitly bounded registry transaction. Preparation checks the
exact eight expected values, no subkeys, the original security boundary and
32-bit registry view. Staged deletion uses the same original transacted key;
there is no pathname-delete or nontransactional fallback. Commit is allowed only
after exact revalidation. Conflict, timeout, unsupported API, cancellation or
partial failure preserves uncertainty and forbids retry or fallback. Native
fixtures must establish actual visibility, rollback and conflict semantics;
Linux mocks and cross-compilation cannot establish those Windows properties.

Service deletion marking follows successful installed cleanup. The CLI reports
success only after closing original owners and the borrowed witness, with the
bounded operation context still valid. Its JSON is a final observation, never
cleanup authority for a second process. The old PowerShell Lifecycle protected
root refusal remains in place; this operator API does not yet connect the
customer maintenance wizard or qualify an installed B0/update/rollback/uninstall
journey. Interrupted terminal work requires explicit recovery, never blind retry.
