# Original protected registration and selected-generation retirement

The protected-uninstall transaction has a distinct broker Store capability;
`decommission-service` remains service-only. While the original selected
generation is still held, `PrepareRetiringDecommission` retains its completed
registration pair, selected generation's full physical directory identity and
the protected parents. After the host has cleanly closed the selected execution
reader, `Commit` acquires DELETE-capable handles for those exact original objects.
Changed identities, missing originals, an unclosed reader, a destination collision
or cancellation before the terminal marker refuse without moving anything.

This first transaction accepts only the original selected baseline generation.
Updated lineage and pending stage ancestry require a separate ownership policy
and refuse before the terminal marker. The terminal marker is published once.
A bounded started record is written and read back before any rename. The
registration pair moves to fixed recovery siblings under the same held ProgramData
registrations parent; the entire selected generation tree moves to a fixed recovery
sibling under its held Program Files generations parent. Each move remains on its
own original volume and does not traverse or delete unknown children. A completed
record binds both recovery identities to the marker and started record. Original
handles validate the moved objects before a success receipt. Any fault after the
marker, including a partial move, leaves the marker and all physical evidence in
place for manual recovery; it cannot be retried or adopted as a new approval.
The profile, stock installation, trust floor, execution history and terminal
tombstone are untouched.
